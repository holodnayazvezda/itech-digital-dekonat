# Тинки и MCP

Тинки отвечает на русском и ищет людей, аудитории, услуги и предметы в расписании текущего кабинета. Краткие имена вроде «Маша» и «Саша» используют тот же словарь, что и глобальный поиск. Чат также читает личные уведомления и домашние задания, расписание, статусы заявок и студенческую зачётку. Сотруднику деканата доступны очередь обращений и список задач.

Веб-чат направляет пользователя на экран нужной операции. Отмену, перенос и отправку домашнего задания преподаватель подтверждает в карточке пары. Деканат может внести те же изменения в общем расписании. История чатов хранится в SQLCipher. Сервер проверяет владельца, сохраняет вопрос и ответ одной транзакцией и обрабатывает повтор отправки по идентификатору запроса.

## Подключение модели

Сервер вызывает OpenAI-совместимый API Chat Completions с поддержкой function tools. К базовому URL он добавляет `/chat/completions`. [Документация Chat Completions](https://developers.openai.com/api/reference/resources/chat)

| Переменная сервера | Значение |
| --- | --- |
| `CAMPUS_AI_BASE_URL` | Базовый URL провайдера или прокси, например `https://api.openai.com/v1`. Локальный прокси может использовать HTTP на loopback. |
| `CAMPUS_AI_MODEL` | Идентификатор модели у выбранного провайдера. |
| `CAMPUS_AI_API_KEY` | API-ключ поставщика или прокси. |
| `CAMPUS_AI_API_KEY_FILE` | Альтернатива передаче ключа в окружении. Путь к файлу секрета внутри процесса или контейнера. |
| `CAMPUS_AI_TIMEOUT` | Лимит ожидания модели в секундах, от 1 до 45. Значение по умолчанию 12. |

Ключ приложения получает у поставщика API или владельца прокси. JWT кабинета используется отдельно для доступа к данным кампуса. Передавайте ключ только серверу. Если модель подключена, к выбранному провайдеру уходят вопрос, до пяти предыдущих обменов из того же чата и результаты разрешённых инструментов. При отключённом или недоступном провайдере Тинки отвечает через встроенный навигатор. Транспорт модели вынесен в интерфейс `ModelTransport`. Для перехода на gRPC потребуется реализация этого интерфейса по контракту сервиса.

## MCP по HTTP

`POST /api/campus/mcp` реализует Streamable HTTP с прямыми JSON-ответами и поддерживает `initialize`, `ping`, `tools/list` и `tools/call`. Используйте Bearer JWT обычного кабинета. Список инструментов зависит от роли. Присутствующий заголовок `Origin` должен совпадать с адресом из `CAMPUS_MCP_ORIGINS` (список через запятую). Клиенты Codex и CLI могут подключаться без заголовка Origin. [Спецификация транспорта MCP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)

Для локального сервера на порту Docker по умолчанию зарегистрируйте MCP в Codex:

```sh
codex mcp add tinki-campus --url http://127.0.0.1:8080/api/campus/mcp --bearer-token-env-var CAMPUS_MCP_TOKEN
```

Процесс Codex должен получить JWT кабинета в переменной `CAMPUS_MCP_TOKEN` через окружение. Для удалённого сервера укажите его HTTPS-адрес. После истечения JWT запустите клиент с новым токеном. В HTTP доступны только инструменты чтения, включая `campus_search`, `campus_schedule` и `campus_notifications`. Для учащегося и деканата каталог добавляет инструменты, доступные соответствующему кабинету.

## MCP через stdio

Для доверенного MCP-хоста есть адаптер, который строит каталог из OpenAPI кампуса. Он вызывает операции от имени того же кабинета, включая управление парами, задачи деканата, возврат и повторную подачу заявок. Хосту следует подтверждать операции записи с пользователем перед вызовом. Аннотации `readOnlyHint` и `destructiveHint` помогают отличить их от чтения. API проверяет роль и поля каждого запроса. [Спецификация инструментов MCP](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

Запустите из `solution/` с переменной `CAMPUS_MCP_TOKEN`:

```sh
server/.venv/bin/python -m server.mcp
```

`CAMPUS_MCP_ORIGIN` задаёт адрес кампуса. Значение по умолчанию `http://127.0.0.1:8000`. Для Docker укажите порт, на котором опубликован контейнер. Удалённый API требует HTTPS. Пример конфигурации хоста с путями к локальной установке:

```json
{
  "mcpServers": {
    "irishka-campus": {
      "command": "/absolute/path/solution/server/.venv/bin/python",
      "args": ["-m", "server.mcp"],
      "cwd": "/absolute/path/solution",
      "env": { "CAMPUS_MCP_ORIGIN": "http://127.0.0.1:8000" }
    }
  }
}
```

В stdio поиск называется `campus_irishka_search` и принимает, например, `{"query":{"query":"Маша","category":"people"}}`. Вход выполняется отдельно через API, вне каталога MCP. PDF и вложения возвращаются как embedded resources с MIME и base64.
