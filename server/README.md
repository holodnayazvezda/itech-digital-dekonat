# Python API цифрового деканата

FastAPI выдаёт JWT, загружает персональное расписание и зачётку, хранит обращения и переписку в зашифрованной базе SQLCipher, формирует PDF и отправляет уведомления. Сервер самостоятельно запускается с ресурсами из этой папки. Шрифты и Swagger UI поставляются локально. Для работы API достаточно Python 3.13.

## Локальный запуск

Из корня репозитория выполните команды ниже.

```sh
python3 -m venv server/.venv
server/.venv/bin/python -m pip install -r server/requirements.txt
server/.venv/bin/python -m uvicorn server.main:app --host 127.0.0.1 --port 8000
```

Для разработки можно включить перезапуск аргументами `--reload --reload-dir server`. Проверка готовности обращается к SQLite. Спецификация OpenAPI генерируется из моделей Pydantic и объявлений маршрутов при запуске. [Проверка готовности](http://127.0.0.1:8000/health) · [Swagger UI](http://127.0.0.1:8000/docs) · [OpenAPI JSON](http://127.0.0.1:8000/openapi.json)

## Вход через Swagger

1. Откройте `/docs`. В группе «Сеанс» разверните `POST /api/campus/login`, нажмите **Try it out** и выполните запрос с телом `{"role":"student","password":"CampusDemo2026!"}` для демонстрационного режима. В production используйте пароль настроенной учётной записи.
2. Скопируйте строку из поля `token` в ответе. Нажмите **Authorize**, вставьте строку в поле **CampusJWT** и подтвердите. Swagger самостоятельно сформирует заголовок `Authorization: Bearer …`.
3. Выполните `GET /api/campus/state`. Для первого студента поле `owner` содержит `student`, а поле `role` — `student`. Для второго студента используйте `friend`, для преподавателя — `teacher`, для деканата — `office`.
4. Для проверки согласования подайте заявление от студента, сохраните его `id`, затем войдите как `office`. В **Authorize** завершите прежнюю авторизацию и вставьте JWT сотрудника. Выполните `decision` и вернитесь в кабинет заявителя, чтобы увидеть уведомление.
5. Чтобы отозвать JWT на сервере, выполните `POST /api/campus/logout`. Кнопка **Logout** в окне Swagger очищает авторизацию интерфейса.

Поле `role` во входном запросе содержит логин. Роль и доступ определяются на сервере. Неверный или отсутствующий пароль возвращает 401 в обоих режимах. Демо-пароль опубликован в `server/assets/demo-access.json`.

Access-токен живёт 28 800 секунд. Сервер проверяет HS256, подпись, издателя `campus-atlas`, аудиторию `campus-api`, срок действия, владельца и отзыв по `jti`. Повторный вход выдаёт новый токен. Ключ подписи используется только сервером. JWT передавайте в заголовке запроса. Ответы персонального API имеют `Cache-Control: no-store`.

## Контракт

Общий префикс — `/api/campus`. Все маршруты в таблице, кроме входа, требуют JWT. Каждая операция в Swagger содержит назначение, тип запроса, успешный ответ и применимые ошибки. Входные поля, скрытые от интерфейса роли или владельца, нельзя использовать для изменения полномочий.

| Метод и путь | Доступ и результат |
| --- | --- |
| POST /login | Выдаёт `token`, `token_type` и `expires_in`. Поле `role` исторически содержит ID кабинета |
| POST /logout | Отзывает текущий токен |
| GET /clock | Серверное время ISO 8601, дата YYYY-MM-DD и часовой пояс Europe/Moscow. Доступен до входа, ответ не кешируется |
| GET /state | Личные оценки, начисления по месяцам, Wi-Fi, элективы, обращения, уведомления и переписка. Деканату доступна общая очередь. Занятость помещений и аватары доступны участникам |
| POST /notes/clear | Очищает входящие текущего пользователя до `through_id` включительно. Новые письма сохраняются. Повторный запрос безопасен |
| POST /notes/{note_id}/read | Сохраняет отметку о прочтении для владельца. Повторный запрос идемпотентен. Поле `notes[].read` в `/state` показывает сохранённое состояние |
| GET /schedule | Личные занятия текущего участника. Сотрудник деканата видит все занятия выбранного периода. Параметры `start` и `end` задают даты включительно. Если задан только `start`, возвращает семь дней. Поля `canManage`, `revision`, `cancelled` и `changed` описывают доступ и состояние пары |
| POST /teaching/lesson/{action} | `reschedule`, `cancel` или `homework`. Преподаватель управляет своими занятиями. Сотрудник деканата может менять занятия всех групп. Публикация создаёт уведомления |
| GET /catalog | Каталог услуг из shared/services.js, признаки справок и обязательные поля. Для перевода перечислены программы, доступные конкретному студенту |
| POST /request | Студент подаёт документ или бронь. Преподаватель подаёт бронь. Дискриминатор `kind` выбирает тело. Возвращает `id` и полную сохранённую карточку `record`. При сетевом сбое повторите запрос с тем же необязательным UUID `requestId`. Для того же владельца и содержимого сервер вернёт исходную карточку без второй заявки или уведомления. Другие параметры с тем же UUID вернут `409` |
| POST /clarify | Сотрудник запрашивает дополнительные сведения по ожидающему документу |
| POST /supplement | Владелец отвечает на уточнение и может заменить вложение. Документ возвращается в очередь с тем же ID |
| POST /decision | Сотрудник принимает ожидающую заявку и указывает решение `approved` или `rejected` |
| POST /cancel | Владелец отменяет ожидающую или одобренную бронь |
| GET /attachment/{id} | Исходное вложение для заявителя или сотрудника деканата с исходным MIME-типом и именем файла |
| GET /file/{id} | PDF одобренной электронной справки только для владельца в течение 24 часов после выдачи |
| POST /choose-elective | Студент передаёт код курса и предыдущий выбор. Запись на 4 семестр открыта 1–7 декабря 2026 года включительно по Москве. За пределами периода сервер требует разрешённый режим жюри и явный `juryPreview: true`. Повтор того же выбора сохраняет количество мест |
| POST /reset-wifi | Для студента и преподавателя создаёт демонстрационный пароль с активацией через 5 минут |
| POST /avatar | PNG data URL текущего пользователя, до 2 МиБ |
| POST /group-message | Преподаватель передаёт код группы из `state.teachingGroups`, текст и UUID `requestId`. Сервер создаёт по личному сообщению и уведомлению для каждого студента группы и возвращает точное число адресатов. Повтор с тем же UUID и содержимым безопасен |
| POST /message | Личное сообщение указанному участнику, до 4000 символов |
| POST /letter | Письмо от деканата одному адресату, тема до 140 и текст до 12 000 символов |
| GET /notes/events?after={id} | Поток SSE для авторизованного кабинета, с восстановлением по ID |
| GET /push-key | Публичный VAPID-ключ для подписки браузера |
| POST /subscribe | Привязывает Web Push подписку браузера к текущему кабинету |
| POST /unsubscribe | Снимает привязку endpoint для текущего владельца |
| GET /office/tasks | Общие задачи сотрудников деканата со сроками и ссылками на обращения |
| POST /office/tasks | Добавляет задачу деканата. `title` обязателен, `body`, `due` и `request_id` необязательны |
| POST /office/tasks/{task_id}/status | Устанавливает состояние задачи из поля `complete`. Повтор поля с тем же значением сохраняет исходную дату изменения |
| POST /mcp | Авторизованный доступ на чтение к инструментам Тинки через Streamable HTTP. [Подключение и инструменты](../docs/irishka-mcp.md) |

Время занятий и брони — московское. Даты в JSON имеют формат YYYY-MM-DD. Время создания обращений и уведомлений, срок PDF и активация пароля передаются в Unix-миллисекундах. Даты внутри JWT измеряются в секундах. Начисления в `payments` выражены в рублях.

Для публикации изменения пары передайте `lessonId` из расписания, уникальный UUID в `requestId`, текст в `body` и полученный для пары `revision`. Для переноса также нужны `date`, `time` и `room`. Сервер сохраняет длительность пары. Успешный ответ содержит `lesson`, `recipients` и ревизию расписания `revision`. При 409 загрузите расписание перед повторным редактированием. После потери ответа повторите тот же запрос с тем же UUID.

## Пример обращения

```json
{
  "kind": "document",
  "name": "Справка об обучении",
  "format": "Электронная",
  "values": {"destination": "По месту требования"}
}
```

Для этой услуги нужен `destination`. У других форм набор обязательных полей отличается. Получите его через `/catalog`. В `attachment` можно передать `name`, `mime` и `base64` для PDF, PNG или JPEG до 2 МиБ. Сервер проверяет формат содержимого, ограничения значений и порядок дат. Максимальный размер JSON — 2 900 000 байт.

Для брони передайте, например, `{"kind":"booking","short":"Б-108","date":"2026-11-20","time":"14:00","end":"15:00"}`. Доступный демонстрационный период — с 20 ноября по 28 декабря 2026 года. Шаг выбора и минимальная длительность — 30 минут. Максимальная длительность — четыре часа в интервале 09:00–22:00. Сервер проверяет занятость при подаче и при решении. В спортзале учитывается число оставшихся мест. Пересечение с собственной парой показывается студенту и допускает подачу заявки.

Обращение начинает путь в `pending`. Для документа возможен цикл `pending → clarification → pending`. Деканат переводит `pending` в `approved` или `rejected`. Бронь может перейти из `pending` или `approved` в `cancelled`. При решении уведомление и новая версия заявки сохраняются в одной транзакции. Для бинарного скачивания используйте тот же заголовок авторизации, что и для JSON.

## Ошибки

Ошибки прикладного API возвращают JSON с полем `error`. Клиенту стоит обновить состояние при конфликте.

| HTTP | Значение |
| --- | --- |
| 400 | Неверные даты, недопустимая услуга, значение поля или формат содержимого |
| 401 | Нужен вход, JWT просрочен, повреждён или отозван |
| 403 | У текущего кабинета нет полномочий на действие |
| 404 | Обращение отсутствует или файл недоступен этому участнику |
| 409 | Занятый интервал, исчерпанные места, дубликат или изменившийся статус |
| 410 | Срок доступа к PDF истёк |
| 413 | Превышен лимит тела запроса или содержимого файла |
| 422 | Запрос не соответствует объявленной структуре или типам полей |
| 429 | Достигнут лимит входа. Заголовок `Retry-After` указывает время ожидания в секундах |

## Настройка и развёртывание

| Переменная | Назначение |
| --- | --- |
| CAMPUS_MODE | `demo` для локальной демонстрации, `production` для входа с паролем |
| CAMPUS_JWT_SECRET | Секрет HS256 от 32 байтов. Обязателен в production. В demo по умолчанию сохраняется отдельный случайный ключ в SQLite |
| CAMPUS_ACCOUNTS_FILE | Путь к закрытому JSON-файлу с идентификаторами кабинетов и хешами паролей Argon2id или прежнего формата scrypt. Обязателен в production |
| CAMPUS_DEMO_DB | В production обязателен путь на постоянном диске. Локальный демонстрационный адрес по умолчанию — `~/.local/share/campus-atlas/demo.sqlite` |
| CAMPUS_DB_KEY_FILE | Файл ключа SQLCipher с правами 0600 или 0400. Обязателен в production. Для стандартной демобазы ключ создаётся в `~/.config/campus-atlas/keys/demo.db-key`. Для явно выбранного тестового пути — в `<CAMPUS_DEMO_DB>.db-key` |
| CAMPUS_WIFI_KEY_FILE | Файл отдельного ключа Fernet для демонстрационных паролей Wi-Fi. По умолчанию `<CAMPUS_DEMO_DB>.wifi-key`. В production задайте путь в закрытом каталоге секретов |
| CAMPUS_JURY_PREVIEW | Разрешает любому демонстрационному студенту проверить запись на курс вне официального периода. В деморежиме включён по умолчанию, в production выключен. Явные значения — `1` или `0` |
| CAMPUS_CORS_ORIGINS | Список origin фронтенда через запятую при размещении на другом домене |
| CAMPUS_VAPID_SUBJECT | Контакт оператора Web Push в форме `mailto:…`, по умолчанию демонстрационный адрес |

Пример запуска двух независимых сервисов на Linux ниже. Сначала создайте каталоги для секретов и SQLite, доступные только сервисному пользователю. Следующие команды выполняются из корня репозитория. Пароль утилита запрашивает без вывода в терминал.

```sh
server/.venv/bin/python -m server.database keygen /etc/campus/database.key
server/.venv/bin/python -m server.account /etc/campus/accounts.json student
server/.venv/bin/python -m server.account /etc/campus/accounts.json friend
server/.venv/bin/python -m server.account /etc/campus/accounts.json office
export CAMPUS_MODE=production
export CAMPUS_ACCOUNTS_FILE=/etc/campus/accounts.json
export CAMPUS_DEMO_DB=/var/lib/campus/atlas.sqlite
export CAMPUS_DB_KEY_FILE=/etc/campus/database.key
export CAMPUS_WIFI_KEY_FILE=/etc/campus/wifi.key
# CAMPUS_JWT_SECRET задаётся в секретах хостинга.
server/.venv/bin/python -m uvicorn server.main:app --host 127.0.0.1 --port 8000 --proxy-headers --forwarded-allow-ips=127.0.0.1
```

Для демонстрации кабинета преподавателя также создайте запись `teacher` той же командой.

Сгенерируйте отдельный случайный ключ подписи JWT один раз и сохраните в менеджере секретов. После изменения файла учётных записей перезапустите процесс. После смены ключа JWT все пользователи входят заново. Для веб-клиента соберите `VITE_CAMPUS_AUTH=password npm run build`. Разместите `client/dist/` за HTTPS и направьте API на Uvicorn. Прокси завершает TLS и заменяет клиентские заголовки `X-Forwarded-Proto` и `X-Forwarded-For` собственными. В списке доверенных адресов Uvicorn укажите только свой прокси. Парольная сборка клиента требует HTTPS, а production API отклоняет запросы по HTTP и передаёт HSTS по HTTPS. На каждый процесс действует лимит 20 попыток входа с одного IP за минутное окно и двух одновременных вычислений хеша. Общий лимит на все процессы задавайте на прокси. Для объёмных DDoS нужна фильтрация на стороне хостинга до попадания трафика на сервер. Один процесс Uvicorn и постоянный локальный том подходят для конкурсного стенда. Для нескольких машин потребуется общее серверное хранилище.

Web Push работает при разрешении браузера в защищённом контексте. Сервер сохраняет уведомление в одной транзакции с решением, затем отправляет Web Push на подписанные устройства адресата. На HTTPS или localhost пользователь один раз разрешает системные уведомления при входе, в карточке поданной заявки или в разделе «Уведомления». При уже выданном разрешении клиент автоматически регистрирует Service Worker и сверяет подписку при входе. В разных вкладках одного браузера подписки студента и студенческого офиса сосуществуют. После закрытия вкладки Web Push принимает браузер через службу производителя при разрешённой фоновой работе. При недоступном провайдере открытый кабинет получает те же события по SSE с JWT в заголовке Authorization и автоматически восстанавливает поток после обрыва. Обновление состояния каждые две секунды служит резервом. Для SSE отключите буферизацию на обратном прокси. В разделе «Уведомления» отдельный статус показывает, доступна ли фоновая доставка. Service Worker объединяет дубликаты одного события по идентификатору уведомления. Ключи VAPID хранятся в SQLCipher и должны сохраняться при перезапуске. История уведомлений доступна в кабинете и при отключённых push. Для реальной доставки серверу нужен исходящий HTTPS к провайдеру браузера. Интеграции с реальными университетскими учётными системами, сетевым контроллером и электронной подписью в демонстрационном стенде отсутствуют.

Для сквозной проверки закрытого Firefox выполните из `solution` команду `CAMPUS_TEST_REAL_PUSH=1 npx playwright test web-push.spec.js --project=firefox-desktop`. Тест запускает отдельный стенд с временной БД и обращается к службе Mozilla. Он проверяет принятие системного уведомления через `ServiceWorkerRegistration.getNotifications()` после одобрения брони и закрытия обеих вкладок.

## Хранение, перенос и резервная копия

SQLite работает в режиме WAL. Изменение статусов, подсчёт мест и проверка конфликтующих броней выполняются под `BEGIN IMMEDIATE`. В `records` лежат заявки, в `notes` уведомления, в `messages` диалоги, в `attachments` файлы. Таблицы аватаров, элективов, сетевых реквизитов, подписок и VAPID-ключей совместимы с прежней базой. Таблицы `settings` и `revoked` добавляются при запуске. Учебные данные, схемы услуг и начисления находятся в `assets/campus.json`. Клиент получает личные оценки и суммы только в состоянии своего кабинета.

Пароль университетской сети доступен своему владельцу для показа и копирования. В SQLite хранятся его шифротекст Fernet и время активации. При первом запуске сервис создаёт ключ в отдельном файле с правами `0600`; каталог этого файла должен существовать. Смена JWT-ключа не влияет на сетевые реквизиты. При обновлении старой базы сервис в одной транзакции шифрует прежние значения, сохраняет время активации и удаляет исходный столбец. Исторические резервные копии старого формата могут содержать открытые сетевые пароли.

Сохраняйте отдельную защищённую резервную копию файла `CAMPUS_WIFI_KEY_FILE`. При восстановлении укажите тот же ключ вместе с восстановленной SQLite. Если зашифрованная база открыта без соответствующего ключа, запуск завершится с ошибкой до приёма запросов.

SQLCipher шифрует страницы базы и журнала WAL с помощью AES-256 и проверяет их подлинность. Под защиту попадают в том числе тексты диалогов, отправители и получатели, заявки, содержимое вложений и ключи Web Push. Ключ базы создаётся из 32 случайных байтов. При потере ключа восстановление требует его резервной копии. Сервер расшифровывает данные для авторизованных запросов. Администратор с доступом к базе и ключу может прочитать переписку. Для сквозной конфиденциальности от оператора понадобился бы отдельный клиентский протокол. Синтетические учебные планы, оценки и справочники в поставляемых JSON и JS доступны вместе с исходниками. Реальные данные должны поступать через защищённое хранилище и авторизованные маршруты. [Устройство SQLCipher](https://www.zetetic.net/sqlcipher/design/)

Новые пароли входа получают индивидуальную случайную соль и хеш Argon2id с памятью 64 МиБ, тремя проходами и одной линией параллелизма. Владельцы прежних scrypt-хешей сохраняют доступ. Чтобы перевести учётную запись на Argon2id, повторно задайте пароль через `server.account` и перезапустите API. Содержимое пароля не выводится. [Рекомендации OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

### Перенос открытой базы

Остановите все процессы, меняющие исходную базу, включая исторический Node-прототип. На старом демостенде файл назывался `decanat-atlas-demo-v2.sqlite` в системном временном каталоге. Подготовьте закрытые каталоги. Ключ создайте один раз. Команды ниже выполняются из корня репозитория.

```sh
server/.venv/bin/python -m server.database keygen /etc/campus/database.key
server/.venv/bin/python -m server.database migrate /path/old.sqlite /var/lib/campus/atlas.sqlite --key /etc/campus/database.key
```

Укажите новый путь в `CAMPUS_DEMO_DB`, а ключ — в `CAMPUS_DB_KEY_FILE`. Если Wi-Fi уже использовался, укажите в `CAMPUS_WIFI_KEY_FILE` прежний ключ Wi-Fi. Утилита читает согласованный снимок, проверяет подлинность страниц и целостность структуры, затем публикует новый файл. Существующий файл назначения защищён от перезаписи. Проверьте `/health`, историю заявок и сообщений и доступ к вложениям. До вывода исходного файла из эксплуатации он и его прежние резервные копии остаются читаемыми.

### Резервная копия, восстановление и смена ключа

Создайте отдельный ключ резервной копии и сохраните его в хранилище секретов. Штатный экспорт поддерживает работающий сервер в режиме WAL. Каждый снимок требует нового имени файла.

```sh
server/.venv/bin/python -m server.database keygen /secure/keys/backup.key
server/.venv/bin/python -m server.database backup /var/lib/campus/atlas.sqlite /backups/atlas-01.sqlite --source-key /etc/campus/database.key --key /secure/keys/backup.key
```

Для восстановления остановите API и направьте его на проверенный снимок и соответствующий ключ. Восстановите также ключ Wi-Fi, конфигурацию аккаунтов и секрет подписи JWT из защищённых копий. Для смены ключа рабочей базы остановите запись, выполните ту же команду `backup` в новый файл с новым ключом назначения и переключите оба пути вместе. Храните ключи отдельно от передаваемых копий базы. [API и экспорт SQLCipher](https://www.zetetic.net/sqlcipher/sqlcipher-api/)

### Проживание и оплата общежития

Поле `housing` в авторизованном ответе `GET /api/campus/state` содержит выделенное пользователю общежитие, комнату, дату начала и помесячные начисления. При отсутствии места возвращается `null`. Суммы указаны в рублях. Список `charges` содержит срок оплаты, начисленную и внесённую суммы и дату последнего поступления. Исходный демонстрационный лицевой счёт задан в `assets/campus.json` в коллекции `housing`. Банковская интеграция в прототипе отсутствует.

Первичное заявление на заселение проходит через `POST /api/campus/request` и обычную очередь согласования. Заявка на рассмотрении или уточнении, а также уже предоставленное место исключают повторную подачу (HTTP 409). Одобрение открывает студенту карточку выбранного общежития с пустой историей начислений. Ремонт и поддержка доступны как отдельные виды обращений.
