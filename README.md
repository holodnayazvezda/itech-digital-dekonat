# Цифровой деканат iTech

Приложение объединяет учебные сервисы и цифровой документооборот. Студент видит свои занятия, оценки, план, выплаты и проживание, оформляет заявления и брони. Преподаватель переносит и отменяет свои занятия, отправляет домашние задания и сообщения группам. Деканат рассматривает обращения, отвечает пользователям и ведёт задачи. Справочники и личные сведения вымышлены.

Приложение для вымышленного вуза iTech.

Вход выполняется по логину и паролю из следующего раздела. Это демонстрационный кабинет вымышленного вуза iTech; доступы предназначены для проверки жюри.

## Вход и роли

Роль определяется сервером по учётной записи: студент получает личные учебные данные и заявки; преподаватель — свои занятия и группы; декан — преподавательские возможности и работу со структурой факультета; сотрудник деканата — рассмотрение обращений, переписку и задачи. Два студенческих аккаунта позволяют проверить изоляцию личных данных.

Форма принимает логин и пароль. Глазок внутри поля переключает видимость. В демосборке блок «Доступ для жюри» подставляет данные выбранного пользователя и показывает роль.

| Логин | Пароль | Кабинет |
| --- | --- | --- |
| `student` | `ArinaStudy2026!` | Студент · Клёнова Арина Дмитриевна |
| `friend` | `NikitaStudy2026!` | Студент · Мартынов Никита Романович |
| `teacher` | `VeraTeach2026!` | Преподаватель · Лесова Вера Андреевна |
| `dean-data` | `ElenaDean2026!` | Декан · Орлова Елена Николаевна |
| `office` | `OfficeHelp2026!` | Сотрудник деканата |

У каждого демонстрационного пользователя свой пароль. Данные находятся в `client/src/shared/domain/demo-access.json`. Сервер проверяет пароль в обоих режимах. Сборка `VITE_CAMPUS_AUTH=password npm run build` показывает пустые поля и использует персональные аккаунты из `CAMPUS_ACCOUNTS_FILE`. Инфраструктурные секреты в клиент не передаются.

## Основные сценарии

- Расписание открывает день или неделю, карточку занятия, преподавателя и аудиторию. Выгрузка формирует ICS или CSV для выбранного периода. Перенос и отмена пары проходят серверную проверку занятости и уведомляют группу.
- Зачётка показывает баллы, аттестации и задолженности. Учебный план связан с программой, семестрами и выбором дисциплин. Вне периода записи доступен явно включённый режим демонстрации жюри.
- Документы и заявления имеют разные поля и вложения. История объединяет документы и брони, поддерживает уточнение и решение. Одобренная электронная справка доступна владельцу для скачивания 24 часа.
- Бронирование выбирает корпус, помещение, дату и интервал от 30 минут до четырёх часов. Сервер повторно проверяет занятость при согласовании. Спорт учитывает оставшиеся места.
- Финансы показывают стипендию или зарплату по роли. Общежитие содержит комнату, контакты и начисления. У студента без места есть отдельная форма заселения.
- Персоналии и структура связывают факультеты, кафедры, программы, группы и людей. Чаты поддерживают личные ответы, преподаватель может разослать сообщение своей группе.
- Навигатор ищет помещение и строит маршрут по этажам с последовательными шагами. Карты вымышлены, формат замены описан отдельно.
- Тинки использует данные текущего кабинета. Встроенные сценарии работают без внешнего ключа. Для внешней модели настраивается серверный провайдер. Прикладные изменения требуют подтверждения пользователя.

Реальные банковские операции, электронная подпись и интеграция с университетскими учётными системами в прототипе отсутствуют.

## Архитектура и файлы

React управляет оболочкой и экранами. URL и историю браузера обслуживает адаптер History API, Preact Signals хранит состояние кабинета, Vite собирает клиент. FastAPI проверяет JWT и права, выполняет операции и хранит изменения в SQLCipher. Один процесс `server.web:app` может обслуживать API и готовый `client/dist/`.

| Путь | Назначение |
| --- | --- |
| `client/src/` | Точки входа, экраны React, оболочка React, темы, карта и клиент API |
| `client/src/shared/domain/` | Календарь, справочники, каталог услуг, правила поиска и серверные часы клиента |
| `client/public/` | Иллюстрации, план кампуса JSON, манифест приложения и Service Worker |
| `server/` | FastAPI, OpenAPI, авторизация, транзакции, файлы и уведомления |
| `server/assets/` | Синхронизированные демоданные и шрифт для PDF |
| `client/scripts/` | Подготовка справочников, локальной поисковой модели и карты |
| `client/test/` | Модульные проверки JavaScript и браузерные сценарии Playwright |
| `server/tests/` | Контракт API, права, конкурентные операции и сохранность данных |
| `design/` | Актуальный макет Figma и переносимый файл `.fig` |
| `docs/` | Формат карты, интеграция Тинки и снимки интерфейса |

Браузер получает время сервера, выполняет вход и загружает личное состояние и расписание. API является источником изменяемых данных. После успешного запроса клиент применяет ответ и обновляет снимок кабинета. Для заявок и ряда групповых операций повтор с тем же идентификатором безопасен.

## Локальный запуск

Команды выполняются из корня репозитория. Проверены Node.js 24 и Python 3.13.

```sh
python3 -m venv server/.venv
server/.venv/bin/python -m pip install -r server/requirements.txt
cd client
npm ci
npm run dev
```

Клиент доступен на http://127.0.0.1:4197, API — на http://127.0.0.1:8000, Swagger — на http://127.0.0.1:8000/docs. Для отдельных процессов используйте `npm run dev:client` и `npm run dev:server`. В Windows замените путь к интерпретатору на `../server/.venv/Scripts/python.exe` (из каталога клиента).

## Данные, время и уведомления

`npm run dev` и `npm run build` выполняют `sync:rooms` и устанавливают локальную поисковую модель. `sync-rooms.js` читает `client/public/campus-map.json`, обновляет `client/src/shared/domain/room-catalog.json` и синхронизирует `server/assets/campus.json`. `sync-directory.js` собирает структуру университета из общих справочников. При изменении помещений пересоберите клиент и перезапустите API.

До показа кабинета `GET /api/campus/clock` возвращает серверное время по Москве. Оно повторно приходит в `state`. Между ответами используется `performance.now()`. При смене суток выбранное «Сегодня» переходит на новый день, другая выбранная дата сохраняется. Ручная настройка демо-времени на компьютере действует до перезагрузки или смены дня.

Уведомления доступны в настройках кабинета. Счётчик и прочтение сохраняются на сервере. Разрешение браузера включает Web Push, SSE обновляет открытый кабинет, опрос служит резервом. На iPhone системные уведомления включаются из установленного на экран «Домой» приложения по HTTPS. [Условия Web Push в WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

База и ключи хранятся вне исходников. Перед обновлением действующего сервера сохраните согласованную копию SQLCipher, ключ базы, ключ Wi-Fi, аккаунты и секрет JWT. [Хранение и восстановление](server/README.md#хранение-перенос-и-резервная-копия)

## Сборка и проверки

```sh
cd client
npm test
npm run build
../server/.venv/bin/python -m pip install -r ../server/requirements-dev.txt
cd ..
server/.venv/bin/python -m pytest -q -o cache_dir=server/.pytest_cache server/tests
cd client
npx playwright install chromium firefox webkit
CAMPUS_TEST_IPHONE=1 npx playwright test --workers=1
```

Браузерные тесты запускают свой API, клиент и временную БД на портах 8261 и 4261. Они фиксируют серверные часы на 20 ноября 2026 года, 09:50 МСК. Для одного движка добавьте `--project=chromium-desktop`, `--project=chromium-mobile`, `--project=firefox-desktop` или `--project=webkit-mobile`.

Готовая сборка обслуживается командой `server/.venv/bin/python -m uvicorn server.web:app --host 127.0.0.1 --port 8080`. При раздельном размещении клиент получает адрес API из `VITE_API_ORIGIN`, сервер разрешает origin через `CAMPUS_CORS_ORIGINS`. Значения `VITE_*` входят в публичную сборку.
