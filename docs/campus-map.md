# Формат поэтажной карты

Приложение загружает `client/public/campus-map.json` со своего статического хостинга относительно базового URL приложения. Vite копирует файл в `client/dist/campus-map.json`. После публикации администратор может заменить этот файл отдельно от сборки клиента. Для немедленного обновления настройте HTTP-кэширование файла с перепроверкой через ETag. Карта демонстрационного кампуса содержит вымышленные данные. Весь файл доступен пользователю как публичный ресурс.

## Замена карты на сервере

[Готовый пример JSON](campus-map.example.json) содержит два этажа, лестницу и аудиторию. Скопируйте пример, задайте свои корпуса и координаты, затем выполните из папки `solution`:

```sh
npm run map:check -- /tmp/university.json
npm run map:install -- /tmp/university.json ./public
```

Первой командой можно проверить файл отдельно. Вторая заново проверяет данные и атомарно заменяет `campus-map.json` в указанном каталоге. При ошибке текущая карта продолжает работать. Для работающего статического сайта укажите каталог, из которого веб-сервер раздаёт клиент, например `./dist`. Изменение видно при следующем открытии навигатора. Чтобы последующая сборка включала тот же план, храните его и в `public`. Для отката установите сохранённую предыдущую версию той же командой.

## Геометрия и каталог

- `buildings[]` задаёт порядок корпусов, `floors[]` порядок этажей. Идентификаторы — строки. Код этажа произвольный, включая `"-1"` и `"M"`. Поле `shortLabel` меняет короткую подпись кнопки этажа. `aliases` корпуса или места задаёт массив дополнительных поисковых названий.
- `viewBox` корпуса задаёт начало X и Y, ширину и высоту. Необязательный SVG-путь `footprint` описывает общий силуэт здания, включая крылья и внутренние дворы. Все этажи такого корпуса используют общий масштаб и систему координат. При ручном переключении между ними сохраняются приближение и положение плана. При переходе в другой корпус или на этаж с другой системой координат карта показывает общий вид. На каждом уровне рендерер рисует серый силуэт, а поверх него — действующий `floor.outline`. Для полного этажа можно использовать одну и ту же строку пути в обоих полях. Для неполного этажа задайте только существующую часть в `outline`, помещениях и графе. Серые крылья остаются ориентиром, не принимают нажатия и не участвуют в маршруте. У схем прежнего формата без `footprint` поддерживается индивидуальный `floor.viewBox`.
- `entryFloor` задаёт ID начального этажа. Когда он пропущен, карта открывает этаж с узлом `entranceNode` или первый в массиве, если вход отсутствует.
- `outline` и `places[].path` содержат команды SVG Path: линии, дуги, кривые, составные контуры. Правило `evenodd` позволяет вырезать дворы и внутренние отверстия. `fixtures` и `windows` на этаже — необязательные SVG-пути для мебели и окон, размещённые в тех же координатах. Исходные данные передаются в атрибут `d`, а не исполняются как SVG-разметка.
- `id` места уникален на всей карте. `name` — доступное название, `label` — короткая подпись, `anchor: [x,y]` — позиция подписи. Если место не имеет контура, рендерер покажет круглую пиктограмму. `zone` добавляет ориентир в поиске и карточке, например «северная галерея».
- Категории `class`, `work`, `office`, `food`, `library`, `water`, `wc`, `lift`, `stairs`, `entrance`, `sport`, `cloakroom`, `service` задают пиктограммы и быстрые фильтры. Учебные аудитории подписаны номерами, у гардероба есть подпись, у остальных мест — пиктограмма. Нажатие открывает полное название. Незнакомая категория отображается общей иконкой. Быстрый фильтр «Студофис» выбирает объекты категории `office`, содержащие «Студенческий офис» или «Студофис» в названии или подписи.
- `code` связывает место с аудиторией расписания. Используйте уникальный номер с префиксом корпуса для переходов из карточки занятия. После обновления файла выполните `npm run sync:rooms`, чтобы синхронизировать список бронирования. Команда также срабатывает перед `npm run build` и `npm run dev`. В список попадут места категорий `class`, `work`, `sport` с кодом. Свойство `bookable: false` исключает конкретное помещение. Необязательные `seats` (целое положительное число) и `equipment` (строка) задают вместимость и оснащение. На размещённом сервере замена статического файла обновляет только карту. Для изменений каталога брони синхронизируйте данные, пересоберите клиент и перезапустите API.

## Маршрут от входа

На каждом этаже поле `nodes` содержит объект вида `{"1-entry":[100,180],"1-lift":[200,180],"1-101":[20,180]}`. Располагайте узлы в проходах, у входов в помещения и на поворотах. Идентификатор узла уникален в пределах корпуса. Поле `links` этажа — список пар соединённых узлов:

```json
[["1-entry","1-lift"],["1-entry","1-101"]]
```

`entranceNode` корпуса задаёт начало маршрута. `node` места указывает его конечную точку на этом этаже. Поле `connections` корпуса описывает переходы между этажами. Пример для одного лифта:

```json
[["1-lift","2-lift","Лифт"],["2-lift","3-lift","Лифт"]]
```

Связи двусторонние. Переходы могут иметь подпись в третьей позиции. Поиск пути использует геометрическую длину рёбер на этаже и постоянную стоимость перехода между этажами. Выводит этапы из найденного пути и показывает отрезки каждого этажа отдельно. Участки, разделённые стеной, соединять нельзя. Контуры помещений сами по себе не задают проходимость. Для этажа или места без маршрутизируемого графа сохраняются просмотр и поиск.

Необязательное поле `metersPerUnit` корпуса задаёт положительное число метров на одну координатную единицу. Повороты показываются на любой схеме с маршрутом. Длина отрезков в метрах появляется при заданном масштабе. Для вымышленных корпусов используется ориентир в 3 метра на ширину основного коридора.

Для демонстрационных корпусов геометрию создаёт `scripts/build-campus-map.py`. На плотных этажах короткий номер аудитории отображается на самой карте. Поиск и карточки места используют полный код с корпусом. Масштабирование открывает подписи соседних комнат. При выборе из списка карта приближает помещение.

После изменения файла проверьте схему командой `node --test test/campus-map.test.js` из папки `solution`. При несовместимой версии, неверных координатах или оборванной ссылке в данных интерфейс покажет ошибку загрузки и кнопку повторной попытки.

Команды npm в этом документе выполняются из `client/`. Синхронизация копирует карту и справочники в `server/assets/`, чтобы API работал независимо от исходников клиента.
