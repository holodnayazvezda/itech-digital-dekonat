# Требования и приёмка

Источник всех требований в этой таблице — [задание VibeCoding](https://challenge.mgimo.ai/cabinet/nominations/vibe-coding), снимок [vibe-coding.txt](../sources/task/vibe-coding.txt) от 20.11.2026. Столбец «Как проверим» — наша конкретизация, а не дополнительные правила организатора. Состояние локального прототипа и проверенные сценарии описаны в [дизайне и реализации](../design/README.md).

## Обязательное ядро

| ID | Требование организатора | Как проверим |
| --- | --- | --- |
| R01 | Рабочий прототип по браузерной ссылке | Открыть опубликованный URL в чистой сессии и пройти основной путь |
| R02 | Вход по логину/паролю или иным способом | Успешный вход, ошибка при неверных данных, выход и повторный вход |
| R03 | Профиль: ФИО, факультет, направление, курс, группа | Все пять значений доступны после входа и принадлежат текущему демо-студенту |
| R04 | Расписание на сегодня и неделю | Оба представления показывают согласованные занятия, дни и время |
| R05 | Аудитория и преподаватель | Они видны у каждого занятия, включая раскрытие на телефоне |
| R06 | Заметные изменения и переносы | У изменённой пары понятны новое время/место и факт изменения; визуальная метка не зависит только от цвета |
| R07 | Оценки и зачёты по дисциплинам | Различаются оценка, зачтено, ещё не оценено и задолженность; нет фиктивного нуля вместо отсутствующей оценки |
| R08 | Сессия и понятная картина успеваемости | Видны даты/статусы аттестаций и понятные действия по незакрытым дисциплинам; правила сводных чисел раскрыты |
| R09 | Заказать справку или подать заявление онлайн | Заполнить форму, отправить, увидеть созданную запись и получить понятную ошибку при неполном вводе |
| R10 | Статус заявки | После отправки видны номер и настоящий сохранённый статус; после обновления страницы запись остаётся |
| R11 | Новости и объявления деканата | Доступен содержательный список и полный текст; даты и адресаты согласованы с демо-данными |
| R12 | Напоминания о дедлайнах и изменениях | Есть примеры обоих типов и понятный переход к соответствующему событию |
| R13 | Все основные сценарии на телефоне от 360 px | На 360 px пройти вход, профиль, расписание, оценки, заявку и уведомления; проверить клавиатуру и отсутствие обрезанных действий |
| R14 | Данные сохраняются | Новая заявка и изменяемые пользовательские состояния переживают перезагрузку и новый вход; дополнительно проверим перезапуск приложения |

R03 — пять полей: ФИО считается одним полем. Преподаватель и аудитория относятся к R05, а не к профилю.

## Данные, защита и доступ

| ID | Требование организатора | Как проверим |
| --- | --- | --- |
| R15 | Каждый студент видит только свои данные, включая прямую подстановку адреса | Студент B не читает и не меняет профиль/заявки A через страницу, API, параметры и тело запроса |
| R16 | Пароли не в открытом виде | В БД хеши паролей, в логах и ответах нет паролей; выбранная реализация проверена по официальной документации |
| R17 | Ключи/пароли сервисов не в коде и браузере | Проверить репозиторий, историю, сборку фронтенда, сетевые ответы и логи; секреты только в окружении сервера |
| R18 | Только вымышленные данные студентов и преподавателей | Явно синтетические профили, оценки, контакты, номера, файлы и примеры; отдельная проверка скриншотов и PDF |
| R19 | Без подключений к настоящим системам вуза и без настоящих логинов | Никаких SSO реального вуза, импорта закрытых кабинетов и реальных учётных записей |
| R20 | Публичные данные разрешено парсить | Возможность, а не обязанность. Не подключать парсер, если синтетическое расписание полностью решает задачу демонстрации |
| R21 | Минимум два тестовых студенческих аккаунта с разными данными | Разные профили, расписания/учебные результаты и заявки; обе пары логин/пароль работают у жюри |
| R22 | Аккаунт сотрудника, если есть его кабинет | При реализации сотрудника дать доступ жюри и отдельно проверить его права; отсутствие такого кабинета не нарушает ядро |
| R23 | Доступ из России без VPN, работа до итогов 28 ноября | Проверка с доступного российского подключения без VPN и повторная проверка в период экспертизы; не выдавать местоположение сервера за доказательство доступности |
| R24 | Подходящий стек и возможность масштабирования | Объяснить границы начальной нагрузки, хранение, сессии и путь расширения; не заявлять нагрузочную ёмкость без замеров |

## Дизайн, процесс и комплект

| ID | Требование организатора | Как проверим |
| --- | --- | --- |
| R25 | Удобно, понятно, современно; основные задачи быстро находятся | Проверить путь без объяснений, связность экранов, пустые состояния, ошибки, загрузку, скорость и доступность |
| R26 | Ясно обозначен конкурсный концепт, не официальный сервис | Заметная естественная подпись на входе и внутри кабинета |
| R27 | Нельзя официальный логотип вуза | Собственная графика; название/реалии вуза допустимы, но не обязательны |
| R28 | Разрешающие лицензии библиотек, шрифтов, иконок, изображений | Реестр зависимостей и ассетов с источником, лицензией и нужной атрибуцией |
| R29 | Код пишут ИИ-ассистенты, автор ставит задачи и проверяет результат | Сохранять реальные промпты, решения, диффы, ошибки и результаты проверок по этапам |
| R30 | Обязательное описание процесса, PDF или документ по ссылке, со скриншотами | Покрыть все шесть пунктов из раздела «Что отправить», см. [SUBMISSION.md](SUBMISSION.md) |
| R31 | Прототип, тестовые аккаунты и исходники доступны жюри | В приватной сессии проверить URL, доступ к репозиторию/архиву и инструкции запуска |
| R32 | Видео до 5 минут необязательно, но приветствуется | Если делаем — показать реальную работу студента, включая телефон, уложиться в лимит |

## Не предписано заданием

Конкретный фреймворк и хостинг, ML-модель, собственное обучение, встроенный ИИ-чат, несколько ИИ-провайдеров, субагенты, кабинет преподавателя/сотрудника, регистрация новых пользователей, интеграция с вузом, реальная выдача юридически значимой справки, установка приложения из магазина. Не превращать упоминание технологии в критерии в обязанность её добавить.

Отдельные реальные интервью также не обязательны: задание просит описать результаты, **если** спрашивали однокурсников. Нельзя представлять синтетические отзывы и гипотезы как проведённое исследование.
